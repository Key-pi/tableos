# Схема зала, заказ на стол с планшета, бронь (PQ-052)

Подробно: `docs/architecture/FLOOR_PLAN.md`. Три шага, каждый — свой модуль,
каждый проверен владельцем. Порядок блокировок — `locks.md`.

- **Схема:** залы; расставляют владелец и менеджер; расстановку пишет только
  `save_hall_layout` (зал целиком); статусы столов — `table_states`, по визиту.
- **Заказ на стол** (модуль `module_table_orders_enabled`):
  официант/бармен/менеджер/владелец; заказ сразу «Принят». Гость без бота —
  анонимный гость визита (не один на заведение): у него нет
  `telegram_account` — без сообщений, рассылок, бонусов, по коду не
  находится. Настоящий гость — по коду, бонусы только ему. Быструю продажу к
  столу не привязывать.
- **Бронь** (модуль `module_reservations_enabled`): только персонал в Mini App
  и Admin (официант, кассир, менеджер, владелец); пишет только
  `apps/tables/reservations.py`. 2 часа по умолчанию; метка на схеме — за
  час; через 15 минут — «опаздывают»; «не пришли» — вручную; пересечение
  броней одного стола проверяется под блокировкой стола; «Пришли» открывает
  визит или (по ответу «это гости брони») привязывается к сидящей компании.

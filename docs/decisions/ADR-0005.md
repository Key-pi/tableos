# ADR-0005: Публичные пути импорта сохраняются при внутреннем упрощении

**Статус:** принято
**Дата:** 2026-07-27

## Контекст

В репозитории были `interfaces.py`, `repositories.py`, пустые модули сервисов и задач и мелкие обёртки-селекторы. Аудит показал, что у ряда интерфейсов нет собственных потребителей, часть репозиториев дублирует селекторы ORM, а один цикл задача/сервис создан локальными импортами. Однако эти пути могут динамически использоваться Django Admin, autodiscovery Celery, management-командами или внешними интеграциями; удалять их по одному `rg` небезопасно.

## Решение

Упрощать структуру только через миграцию с приоритетом совместимости:

1. зафиксировать текущий API и путь импорта и характеризующие тесты;
2. создать новый API у владельца там, где это действительно нужно;
3. оставить старый путь тонким реэкспортом с предупреждением об устаревании, без логики;
4. перевести собственных потребителей и проверить динамические регистрации;
5. удалить прослойку только после согласованного периода, поиска потребителей и отдельной проверки заметок к выпуску.

Новые общие файлы интерфейсов, репозиториев и политик запрещены без задокументированного потребителя и инварианта. Сохранение совместимости не означает сохранения старой архитектуры навсегда.

## Последствия

Положительные:

* рефакторинг не ломает скрытые импорты и точки входа;
* преждевременные абстракции удаляются по доказательству, а не по впечатлению;
* будущие участники получают ясное правило, куда помещать новую логику.

Ограничения:

* временно существуют тонкие прослойки;
* каждое удаление требует инвентаризации динамических потребителей, а не только статического поиска;
* срок устаревания должен быть виден в дорожной карте и документации выпуска.

## Область и проверка

Применяется к любому переносу или удалению Python-модуля, селектора, сервиса, репозитория, интерфейса и импорта задачи Celery. Перед удалением выполняются статический поиск импортов, проверки приложений и Admin Django, проверка регистраций Celery и точечные тесты. В находке аудита отмечается уверенность, и автоматическое удаление не допускается при `AMBIGUOUS_PRODUCT_DECISION` или неясном внешнем потребителе.

Применено в B5 (удаление модулей без потребителей, см. `docs/audits/ARCHITECTURE_AUDIT.md`).

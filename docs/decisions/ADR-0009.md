# ADR-0009: Каналы заказа — одна модель заказа, счёта и оплаты

**Статус:** Accepted (решение владельца 2026-10-23)\
**Дата:** 2026-10-23\
**Связано:** PQ-012, ADR-0007, `docs/product/ECOSYSTEM_DIRECTION.md`,
`docs/architecture/PICKUP.md`

## Контекст

Продукт вырос из заказа за столом, и многое в коде предполагало стол.
Теперь каналов несколько: стол, самовывоз, затем доставка и отправка
почтой. Владелец не хочет плодить параллельные сущности вида
«ЗаказДоставки», «СчётДоставки» под каждый канал.

## Решение

1. **Одна модель на понятие.** `Cart`, `Order`, `Bill`, `Payment`,
   `BonusTransaction` одни для всех каналов. Канал — атрибут:
   `Cart.channel` (что выбрал гость) и `Order.channel` (как получает).
2. **Данные канала — поля заказа, а не новые модели.** Общие для удалённых
   каналов — `Order.requested_for` (к какому времени; пусто — как можно
   скорее). Доставка добавит адрес и стоимость доставки полями заказа и
   своими проверками в сервисе.
3. **Поведение канала — в одном модуле на семейство:**
   - стол — `apps/tables` (сессии, визиты) и `apps/billing/table_bills.py`
     (счета стола, запросы счёта);
   - удалённые каналы с предоплатой — `apps/billing/remote_orders.py`
     (котировка, оформление, проверка перевода); канал включается
     записью в `REMOTE_CHANNELS`, предоплатные перечислены в
     `Order.PREPAID_CHANNELS`.
   Ядро счёта (`apps/billing/services.py`: создание счёта, оплата, бонусы,
   изменения, аннулирование) про каналы не знает.
4. **Меню по каналам** — отметки на позиции (`MenuItem.available_*`), не
   отдельные меню.
5. **Настройки** — флаг модуля на канал; общие для удалённых каналов —
   реквизиты для перевода (`transfer_payment_details`) и часы работы
   (`OpeningHours`).
6. Заказ к столу начинается только со сканирования QR стола; остальные
   каналы — кнопкой в боте.

## Последствия

- Новый канал = значение в `Order.Channel`, флаг модуля, отметка в меню,
  запись в `REMOTE_CHANNELS` и свой шаг оформления (для доставки — адрес).
  Отчёты, счета, бонусы, уведомления и Admin работают сразу.
- Код, который различает каналы, проверяет `order.channel`, а не наличие
  стола (`order.table_id`).
- Переименованы поля и модули самовывоза в общие: `pickup_at` →
  `requested_for`, `pickup_payment_details` → `transfer_payment_details`,
  `apps/billing/pickup.py` → `remote_orders.py`, бот — `remote_checkout.py`.

## Применение: доставка (2026-10-23, PQ-032)

Доставка добавлена так, как здесь описано: значение
`Order.Channel.DELIVERY`, флаг `module_delivery_enabled`, отметка
`MenuItem.available_for_delivery`, запись в `REMOTE_CHANNELS` и
`PREPAID_CHANNELS`, шаг адреса в `remote_checkout.py`. Данные канала —
поля заказа (`Order.delivery_*`). Цена доставки — строка заказа
`OrderItem.kind = delivery_fee` без позиции меню, поэтому ядро счёта
по-прежнему не знает о каналах. Подробно — `docs/architecture/DELIVERY.md`.

# Botera Shop — матрица возможностей и реализации

**Последняя сверка с кодом:** 2026-10-24, ветка `clean-project-rules` после B0–B5, самовывоза, доставки, способов оплаты (PQ-033), отправки почтой (PQ-034) и упорядочивания каналов (ADR-0009); находки AA-020–AA-033.\
**Назначение:** одна компактная таблица желаемых возможностей продукта против подтверждённого текущего поведения. Не заменяет полный продуктовый договор в [PRODUCT_SPEC.md](PRODUCT_SPEC.md) и находки по коду в [ARCHITECTURE_AUDIT.md](../audits/ARCHITECTURE_AUDIT.md).

## Обозначения статусов

| Статус | Значение |
| --- | --- |
| CONFIRMED_CURRENT | Основное поведение подтверждено кодом и входит в текущий MVP |
| PARTIAL_CURRENT | Какой-то путь есть, но важные продуктовые условия не доказаны или отсутствуют |
| CODE_IS_BEHIND_SPEC | Желаемое поведение описано, но реализовано не полностью |
| DEFECT | Текущая реализация может нарушить уже заявленный продуктовый инвариант |
| AMBIGUOUS_PRODUCT_DECISION | Прежде чем определять договор реализации, нужен выбор владельца |
| FUTURE_SCOPE | Явно не предлагается как текущий сценарий |

## Сквозные критерии приёмки, требующие характеризующих тестов

Эти договоры высокорисковые даже там, где путь MVP уже есть. Их нужно покрыть тестами до того, как батч изменит соседний код:

1. Партнёр A не может читать, менять, получать уведомление о данных партнёра B или привязывать к ним связь.
2. Отключённый `User` или `EmployeeProfile` не может пользоваться `/staff` или ранее выданным callback персонала.
3. Повторные сканы QR, callback-и смены статуса заказа, запросы распределения по счёту, оплаты и списания, доставки Celery не создают повторных бизнес-эффектов.
4. Прямой интерфейс Admin не может обойти те же правила заказа, счёта, сессии и бонусов, что путь через бота и сервис.
5. Совпадение подписей не может привести к выполнению чужого намерения гостя.
6. Продакшен-инварианты защищены ограничениями и блокировками PostgreSQL; тесты только на SQLite не считаются доказательством конкурентной корректности.

- поле, значение перечисления или флаг без достижимого сценария;
- старое утверждение под заголовком «текущая реализация» без подтверждения в коде;
- статус модели без обработчика перехода;
- имя задачи Celery без идемпотентности и смысла доставки;
- список Admin с фильтром по партнёру без ограниченных связанных выборов, действий, inline и фоновых путей;
- число тестов или результат линтера, скопированные из `PROJECT_CHEATSHEET.md`.

# Деление счёта (PQ-009)

Решение владельца 2026-11-15: персонал делит счёт сам — по позициям (какие
позиции в какой счёт) и поровну на N человек (например, один кальян на
троих). Уточнено 2026-11-16 (ответы владельца на вопросы Claude):

- **поровну на N** — счёт остаётся один, его оплачивают N частями; модель
  распределения позиций по счетам не меняется;
- **по позициям** — строка заказа уходит в другой счёт целиком (3 пива в
  одной строке не разносятся по штукам — для этого есть «поровну»); правило
  «позиция — в одном счёте» (`BillItem.unique_active_order_item_bill_allocation`)
  остаётся;
- сначала — экран персонала (Mini App); в боте — позже.

Делается по шагам; каждый шаг проверяет владелец.

## Шаг 1. Поровну на N частей — сделан 2026-11-16, проверен владельцем 2026-11-18

**Где.** Карточка счёта на экране персонала («Счета» или стол → счёт): кнопка
«➗ Поровну» → выбор числа частей (2–6 одним нажатием или любое 2–20) →
список частей «Часть 1 — 150 грн» с кнопками «Наличные» и «Карта» у каждой;
оплаченная часть показывает «✓ способ». Пока счёт разделён, общие кнопки
«Наличные» и «Терминал» в карточке скрыты (остальные — «Выдать счёт»,
«Оплатить бонусами» — на месте). До первой оплаченной части можно разделить
на другое число или «Не делить».

**Как считается** (`apps/billing/bill_split.py:split_parts_of`): оплаченная
часть — это её оплата; неоплаченные делят поровну то, что осталось к оплате
(`total_amount − paid_amount`), с округлением вниз до копейки, последняя
часть забирает остаток копеек (100 грн на 3 — 33,33 + 33,33 + 33,34). Поэтому
части всегда сходятся с остатком, даже если счёт изменили (PQ-028), часть
оплатили бонусами или обычной оплатой. Обычная полная оплата остатка (бот,
Admin) закрывает и разделённый счёт — неоплаченные части становятся по 0.

**Данные.** `Bill.split_parts` — на сколько частей делят (0 — не делят);
`Payment.split_part` — какую часть оплатила оплата. Ограничение
`unique_paid_split_part_per_bill`: проведённая оплата одной части счёта —
одна, кто бы ни нажал дважды. Admin показывает оба поля только для чтения
(счёт → «Суммы», вкладка «Оплаты»).

**Команды** (`apps/billing/bill_split.py`):
- `split_bill_equally` — 2–20 частей или 0 (не делить), только у открытого
  счёта с остатком и пока ни одна часть не оплачена;
- `pay_split_part` — часть наличными или картой; сумма, которую показал
  экран (`expected_amount`), должна совпасть с текущей — иначе «Сумма части
  изменилась — обновите экран»; оплату пишет `record_payment(split_part=…)`.

**Кто:** владелец, менеджер, кассир этого заведения
(`bill_split.may_split_bills`; экран — `can_manage_billing`), сервис
проверяет в момент действия (активный пользователь и сотрудник, роль, та же
точка). Блокировка — строка `Bill`, как у любой оплаты; две одновременные
оплаты одной части — вторая получает «Эта часть уже оплачена» (тест на
PostgreSQL).

**Mini App:** `webapp/staff_billing.py:bill_split_view`,
`bill_split_pay_view`; карточка счёта (`_bill_json`) отдаёт `split_parts`,
`split` (номер, сумма, оплачена, способ) и `can_split`.

**Чего нет:** в боте разделённый счёт не показан частями — кнопки бота
оплачивают весь остаток; бонусы за счёт по-прежнему по заказам (кешбэк —
гостю заказа).

## Шаг 2. По позициям — следующий

Персонал отмечает строки визита и переносит их в отдельный счёт целиком; в
исходном остаётся остальное. Заказ считается оплаченным, когда оплачены все
счета с его строками.

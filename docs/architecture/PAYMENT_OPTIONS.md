# Способы оплаты удалённых заказов

**Статус:** решение владельца от 2026-10-24 (PQ-033); реализовано на
`clean-project-rules` для самовывоза и доставки.\
**Основание:** способы заказа — модули, которые настраивает владелец, а гость
выбирает из включённого («у нас суть — гибкость»); ADR-0009 — одна модель
заказа, счёта и оплаты на все каналы.

## Решение владельца

У каждого удалённого модуля (самовывоз, доставка, дальше — отправка) владелец
в Admin включает способы оплаты:

- **переводом заранее** — на реквизиты заведения; персонал подтверждает
  поступление, только потом заказ в работе ([PICKUP.md](PICKUP.md));
- **при получении** — самовывоз: на месте; доставка: курьеру; наличными или
  картой. Заказ сразу идёт в работу, персонал отмечает оплату, когда гость
  платит.

Можно включить один способ или оба; если включены оба, гость выбирает при
оформлении. Бонусы можно списать при любом способе — тогда при получении
платится остаток. По умолчанию (и у всех заведений, настроенных до решения)
включён только перевод заранее.

## Как это выглядит

**Гость.** После времени и бонусов, если включены оба способа: «К оплате N
грн. Как оплатите?» — «💳 Переводом сейчас» / «💵 При получении (на месте /
курьеру)». Если способ один, вопроса нет. Итог при оплате при получении: «К
оплате при получении: N грн. Оплатите на месте наличными или картой», без
реквизитов, кнопка «✅ Оформить заказ». Сообщения: «Заказ принят — готовим»
вместо «Оплата подтверждена — готовим».

**Персонал.** Уведомление: «Оплата при получении: N грн (наличные или
карта)». Карточка заказа: «Оплата: при получении, N грн»; обычные шаги
(«Взять в работу», «Готово», …), плюс «💵 Оплачено наличными», «💳 Оплачено
картой» и «❌ Гость не забрал» вместо «Отменить» (переспрашивает; отменяет
заказ, аннулирует счёт с причиной «Отказ гостя», бонусы возвращаются).
Отмечать оплату и отказ может владелец, менеджер или кассир — как
подтверждать перевод. Оплата и статус заказа независимы: заказ можно выдать
и отметить оплату в любом порядке.

**Владелец (Admin, настройки бота, «Сценарии заказа»).** Рядом с каждым
модулем две галочки: «… оплата переводом заранее», «… оплата при получении».
Включённый модуль требует хотя бы одну; перевод требует реквизитов.

## Модель данных

- `Order.payment_timing`: `prepaid` (переводом заранее) / `on_receipt` (при
  получении); пусто у заказов за столом. Миграция `orders.0010` проставила
  `prepaid` всем прежним заказам самовывоза и доставки.
- `PartnerBotSettings.pickup_pay_transfer`, `pickup_pay_on_receipt`,
  `delivery_pay_transfer`, `delivery_pay_on_receipt` (`partners.0010`).
- `Order.REMOTE_CHANNELS` — удалённые каналы; старое имя
  `Order.PREPAID_CHANNELS` оставлено как синоним для существующих импортов.

## Команды

`apps/billing/remote_orders.py`:

- `payment_modes_for(settings, channel)` — включённые способы (перевод —
  только при заполненных реквизитах); `get_remote_quote` отдаёт их в
  `payment_modes`.
- `place_remote_order(..., payment=…)` — отказывает в способе, который
  владелец не включил; записывает `payment_timing`.
- `record_payment_on_receipt(order, actor, method)` — наличные (`cash`) или
  карта (`terminal`) на остаток счёта; повторное нажатие видит оплаченный
  счёт.
- `cancel_unpaid_remote_order(order, actor)` — гость не забрал: счёт
  аннулируется (бонусы возвращаются `reversal`), заказ `canceled`; нельзя,
  если уже есть оплата деньгами.
- `confirm_transfer`, `reject_transfer` — только для `prepaid`.

`transition_order_status` не пускает в работу неоплаченный заказ только с
`prepaid`. Порядок блокировок — как у оплаты: `Bill → Order → GuestProfile`.

Бот: выбор — `rc:<c>:m:<slot>:<0|1>:<t|r>`; последний сегмент
`rc:<c>:p:…:<t|r>` — способ (итог, отправленный до PQ-033, без него —
перевод). Персонал: `staffrccash:<заказ>`, `staffrccard:<заказ>`,
`staffrcno:<заказ>`, `staffrcnoy:<заказ>`.

## Что не сделано

- Частичная оплата при получении (часть наличными, часть картой) — только
  одним способом на весь остаток; смешанную оплату можно провести через
  «Счета и оплаты».
- Наложенный платёж — появится вместе с отправкой почтой.

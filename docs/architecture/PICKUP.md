# Самовывоз

**Статус:** решения владельца от 2026-10-23; реализовано на
`clean-project-rules`.\
**Основание:** PQ-012, [ECOSYSTEM_DIRECTION.md](../product/ECOSYSTEM_DIRECTION.md)
(стол — один из каналов заказа).

## Решения владельца

1. **Оплата — заранее переводом** на реквизиты заведения; гость может
   списать бонусы. Онлайн-оплаты в системе нет.
2. **Время:** «как можно скорее», «через 30 минут», «через 1 час».
3. **Телефон обязателен:** один раз кнопкой «Поделиться номером» в Telegram,
   сохраняется в профиле гостя.
4. **Приём заказов — только в часы работы** из настроек заведения.

## Как это выглядит

**Гость.**

- Без стола корзина — это корзина самовывоза: в меню есть кнопки
  добавления, внизу кнопки «Корзина» и «Оформить».
- За столом при включённом самовывозе «Оформить» спрашивает: «🍽 К столу
  #N» или «🥡 Самовывоз».
- Оформление самовывоза:
  1. телефон (один раз; принимается только собственный контакт гостя);
  2. время (предлагаются только варианты, попадающие в часы работы);
  3. бонусы, если их можно списать («Списать N бонусов» / «Без бонусов»);
  4. итог: сумма, бонусы, **к оплате переводом**, реквизиты и кнопка «Я
     оплатил(а)»; если всё покрыто бонусами — «Оформить».
- Заказ создаётся по нажатию «Я оплатил(а)». Если корзина или доступные
  бонусы изменились после показа итога, заказ не создаётся, гость видит
  новый итог.
- Гость получает сообщения: «Оплата подтверждена — готовим», «Заказ готов
  — можно забирать», либо «Оплата не поступила, заказ отменён».

**Персонал.** Уведомление о новом заказе содержит время, телефон и сумму
перевода. В карточке заказа вместо «Принять» — «✅ Оплата получена» и «❌
Оплаты нет» (второе сначала переспрашивает). Подтверждать оплату может
владелец, менеджер или кассир. После подтверждения заказ в работе, дальше
обычные статусы: готов → выдан.

**Владелец (Admin, карточка партнёра).** Модуль «Самовывоз», поле
«Реквизиты для оплаты самовывоза» (обязательно при включённом модуле) и
таблица «Часы работы».

## Модель данных

- `Order.channel` (`table` / `pickup`) и `Order.pickup_at` (пусто — как
  можно скорее). У самовывоза нет стола и сессии.
- `Payment.Method.TRANSFER`, `Order.PaymentMethod.TRANSFER`.
- `GuestProfile.phone`.
- `PartnerBotSettings.pickup_payment_details`.
- `OpeningHours` (`apps/partners/models.py`): день недели, открытие,
  закрытие во времени заведения (`Partner.timezone`); закрытие раньше
  открытия — интервал после полуночи; нет строк — всегда открыто.
- `BillAdjustment.ReasonCode.PAYMENT_NOT_RECEIVED`.

## Команды

`apps/billing/pickup.py`:

- `get_pickup_quote` — сумма, доступные бонусы, к оплате, реквизиты, слоты.
- `place_pickup_order` — в одной транзакции: блокировка гостя и корзины,
  проверка часов и сумм, `create_order(channel=pickup)`, персональный
  счёт (`issue_bill`), при выборе — `pay_bill_with_bonuses`, уведомление
  персонала.
- `confirm_pickup_payment` — `record_payment(method=transfer)` на остаток,
  затем `accepted`.
- `reject_pickup_payment` — аннулирование счёта с причиной «Оплата не
  поступила» (бонусы возвращаются записью `reversal`), затем `canceled`.

Порядок блокировок подтверждения и отказа: `Bill → Order → GuestProfile`,
как у оплаты. `transition_order_status` не даёт перевести неоплаченный
самовывоз в `accepted` в обход подтверждения.

Бот (`bot/handlers/pickup.py`) не хранит состояние: шаги идут через
callback-и `pk:t:<slot>`, `pk:b:<slot>:<0|1>`,
`pk:p:<slot>:<0|1>:<итог в копейках>:<к оплате в копейках>`, `pk:x`; выбор
канала — `co:table` / `co:pickup`; персонал — `staffpkok:<заказ>`,
`staffpkno:<заказ>`, `staffpknoy:<заказ>`.

## Что не сделано

- Скриншот перевода от гостя — пока гость только нажимает «Я оплатил(а)».
- Автоотмена заказа, по которому никто не подтвердил оплату.
- Отдельная пауза приёма («завал») — только часы работы.
- Доставка и отправка — следующие каналы (ECOSYSTEM_DIRECTION.md).

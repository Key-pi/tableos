# Языки бота и Admin

Решение владельца — PQ-040. Бот говорит с гостем на его языке, владелец может
заменить любой текст гостя своим, персонал и Admin работают на выбранном
языке. Документация остаётся русской.

## Как устроено

- **Тексты в коде** пишутся по-русски и оборачиваются в `_()` из
  `core/i18n.py`. Значения подставляются после перевода:
  `_("Сумма: {total} грн", total=order.total_amount)`. HTML экранирует
  вызывающий (`escape_html`), как и раньше.
- **Каталог.** Переводы на украинский и английский —
  `locale/uk/LC_MESSAGES/django.po` и `locale/en/LC_MESSAGES/django.po`;
  русский — сам текст в коде. Строки темы Admin (django-unfold, английские
  msgid) — отдельно, в `theme.po` того же каталога. Оба файла собираются в
  `django.mo` скриптом `infrastructure/scripts/messages.py` (без GNU gettext):

  ```bash
  python infrastructure/scripts/messages.py update   # новые тексты в каталоги
  python infrastructure/scripts/messages.py check    # что не переведено
  python infrastructure/scripts/messages.py compile  # .po → django.mo
  ```

  Тест `core/tests_i18n_catalog.py` падает, если какой-то текст кода не
  переведён, если в переводе другие подстановки `{…}` или HTML-теги, если в
  каталоге остались тексты, которых в коде нет, или `django.mo` устарел.
- **Свои тексты владельца** — `apps/partners/models.py:BotText`: заведение,
  язык, текст каталога (русский msgid) и свой вариант. Свой текст сильнее
  каталога только для этого заведения и языка. Подстановки в нём те же, что в
  тексте каталога; если свой текст сломан (неизвестная подстановка, лишняя
  скобка), бот берёт текст каталога, а не падает.
- **Контекст обновления.** `bot/middlewares/partner_runtime.py` после проверки
  партнёра определяет язык (`bot/services/language.py:language_context`) и
  выполняет обработчик внутри `core.i18n.texts(язык, свои_тексты)`. Язык и
  свои тексты живут в `asgiref.local.Local` — у каждого обновления свои, они
  переходят в `sync_to_async` (проверено тестом
  `core/tests_i18n.py:OwnerTextTests.test_concurrent_updates_keep_their_own_language_and_texts`).
  `data["language"]` доступен обработчикам.
- **Ввод гостя.** Подпись кнопки, пришедшая текстом, сравнивается со всеми
  языками: `core.i18n.variants(текст)`.

## Какой язык у человека

`apps/partners/languages.py:choose_language`, по порядку:

1. язык, выбранный гостем в боте (`GuestProfile.language`), если заведение
   его ещё предлагает;
2. язык сотрудника (`User.language`) — активный сотрудник этого заведения;
   для персонала доступны все три языка;
3. язык Telegram (`language_code`), если заведение его предлагает;
4. основной язык заведения.

Настройки заведения (`PartnerBotSettings`): `default_language` — основной
язык, должен быть среди включённых; `language_uk`, `language_ru`,
`language_en` — какие языки предлагаются гостям. Новый бот говорит на языке
платформы (`LANGUAGE_CODE`, по умолчанию украинский) и предлагает все три.
Боты, существовавшие до языков, миграцией `partners.0015_languages`
оставлены русскими: основной русский, включён только русский.

Гость меняет язык в «Мой профиль» → «🌐 Язык» (кнопка есть, если включено
больше одного языка): `guestlang:<uk|ru|en>` или `guestlang:auto` —
«автоматически, как в Telegram». После выбора бот присылает главную
клавиатуру заново на новом языке.

## Тесты

Набор тестов читает тексты так, как они написаны в коде: тестовый запуск
работает с `LANGUAGE_CODE = "ru"` (`core/test_runner.py`). Другие языки
проверяются явно: `core/tests_i18n.py`, `bot/tests_language.py`,
`apps/partners/test_languages.py`.

## Что уже на языках

| Часть | Состояние |
|---|---|
| Механика: каталог, свои тексты, язык обновления, выбор языка гостем | готово |
| Тексты гостя в боте | по частям |
| Тексты персонала в боте | ещё по-русски |
| Уведомления и рассылки (Celery) | ещё по-русски |
| Подписи кнопок и шаблоны заведения (`PartnerBotSettings.button_*`, `*_template`) | ещё одно поле на заведение; перейдут в свои тексты |
| Admin | ещё по-русски |
| Названия меню, категорий и программ | данные заведения, на языке владельца |
